# Развёртывание «Богатого Алхимика» в Amvera

## Обновление действующего приложения — основной маршрут

Проверено 9 сентября 2026: рабочее приложение — «Аллокатор», регион msk0.
Панель: https://cloud.amvera.ru/projects/applications/msk0/allokator
GitHub: https://github.com/lesyaabrikosova-cmd/finance_bot_new, ветка main.
Push в origin/main автоматически запускает сборку и обновление Amvera.
Локальные git-учётные данные для push работают. Отдельный вход в Git Amvera
для обычного обновления не нужен.

1. Проверить состав изменений. Использовать результаты уже прошедших тестов,
   если после них код не менялся; повторять проверки при новых изменениях.
2. Создать коммит нужных файлов и выполнить `git push origin main`.
   Не включать локальную SQLite, WAL/SHM и секреты.
3. Проверить новый коммит в репозитории Amvera и состояние «Запущено».
   В журнале приложения проверить свежий успешный запуск polling.
   Страница логов: https://cloud.amvera.ru/projects/applications/msk0/allokator/logs/run
4. Сообщать отдельно об успешном push и о подтверждённом запуске.
   Если панель недоступна, не выдавать отправку кода за завершённый деплой.

Не готовить архивы, не загружать папки вручную и не настраивать интеграцию
заново, пока существующий маршрут GitHub → Amvera работает. Safari нужен
только для проверки результата; проблемы его доступа не мешают самому push.
Не перезапускать сборку повторно только из-за медленного обновления панели.
Проверять статус с интервалом 30–60 секунд, а не непрерывными UI-запросами.
Рабочие данные находятся в /data; обычный деплой не должен их заменять.

## Создание тестового приложения

1. Тип сервиса: `Приложение`.
2. Тариф: `Пробный` для теста; при нехватке памяти — `Начальный`.
3. Регион: Москва.
4. Загрузка данных: `GitHub`.
5. Репозиторий: `lesyaabrikosova-cmd/finance_bot_new`.
6. Ветка: `main`.
7. Не генерировать `requirements.txt`: он уже находится в корне проекта.
8. Не загружать `.env` и `allocator.db` в папку Code.

В корне репозитория уже есть `amvera.yml`. Он задаёт Python 3.12, запуск
`bot.py`, порт 8080 и постоянное хранилище `/data`.

## Переменные

До первого запуска добавьте в секреты/переменные приложения:

```text
BOT_TOKEN=<токен отдельного тестового бота>
ALLOCATOR_DATA_DIR=/data
HEALTH_PORT=8080
PYTHONUNBUFFERED=1
```

Настоящий токен работающего Railway-бота использовать до переключения нельзя.

## Проверка

После сборки:

1. статус приложения должен стать `Запущено`;
2. технический домен должен отвечать на `/health` текстом `{"status":"ok"}`;
3. тестовый бот должен отвечать на `/start`;
4. после создания тестового профиля перезапустите приложение;
5. профиль должен сохраниться, а в разделе `Репозиторий → Data` должен
   появиться `allocator.db`.

## Рабочая база

Рабочую SQLite загружают в папку `Data`, а не `Code`, и только после остановки
Railway. Перед этим создаётся и проверяется резервная копия. Переключение
настоящего токена выполняется отдельным этапом.
